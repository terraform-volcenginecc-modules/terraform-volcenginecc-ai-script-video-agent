# 可选视频 Provider 适配

## 适用范围

官方 ComfyUI 前后端作为独立程序安装，部署与操作见 [README](../README.zh-CN.md)。本文件说明可选的远程 GPU 视频 Provider：默认 Ark 生成剧本和视频，将 `video_provider` 设为 `comfyui` 后，新建的视频任务调用远程 Comfy API v2。业务适配 API、PostgreSQL Worker 和私有 TOS 继续负责持久任务与媒资。

远程模式需要从目标 ComfyUI 导出可执行的 API 格式工作流。测试数据中的节点和类名只用于协议测试。

## 配置入口

Terraform 参数：

| 参数 | 默认值 | 用途 |
| --- | --- | --- |
| `video_provider` | `ark` | 部署级视频服务选择，仅允许 `ark` 或 `comfyui` |
| `comfyui` | `null` | 远程地址、API 格式工作流、节点映射、输出选择及能力声明 |
| `comfyui_api_key` | 空字符串，敏感 | 远程服务的 Bearer 密钥；选择 ComfyUI 时必填 |

`ark_api_key` 在两种模式下都必填，仍直接写入 `/opt/ai-animation/secrets/ark_api_key`。ComfyUI 密钥直接写入 `/opt/ai-animation/secrets/comfyui_api_key`，API 和 Worker 通过 systemd 凭据读取。密钥正文不进入运行配置或任务快照；Terraform State 仍包含敏感参数，应继续按现有方式保护。

## 真实工作流契约

`comfyui` 对象必须包含下列字段，具体值由实际工作流决定：

| 字段 | 类型与要求 |
| --- | --- |
| `base_url` | 远程服务根地址，可包含挂载前缀，例如服务位于某个子路径；不要追加 `/api/v2`。支持内网 HTTP 或 HTTPS，不接受地址内嵌密码、查询参数、片段 |
| `workflow_json` | **真实 API 格式** JSON 字符串，以节点 ID 为键，各节点含 `class_type` 和 `inputs`；不接受含 `nodes` / `links` 的画布格式 |
| `bindings` | 将业务参数映射到 `{ node_id, input }`；两者必须准确对应工作流中的节点和输入字段 |
| `output_node_id` | 实际输出最终视频的节点 ID |
| `output_index` | 同一节点的视频输出序号，默认 `0`；图片等输出不计入序号 |
| `capabilities` | 明确声明该工作流支持的模式、规格、声音、水印及镜头时长 |

必需映射为 `prompt`、`duration`、`width`、`height`、`seed`。提示词复用现有分镜提示词；`duration` 单位为秒；宽高复用现有画幅与分辨率换算；种子在视频快照创建时固定，重试与恢复沿用。

本阶段不推断帧率、帧数公式、模型名或自定义节点参数。若实际模型只接受帧数，需先确认工作流中的秒数转换节点，或补充有依据的转换契约，再启用该工作流。模型权重及自定义节点应先在远程 GPU 环境准备并验证。

可选映射：

| 映射 | 用途 |
| --- | --- |
| `generate_audio` / `watermark` | 布尔输入。若工作流允许切换，必须映射；没有映射时，只能声明一个固定布尔值，并保证与真实工作流一致 |
| `first_frame` | 首帧输入字段 |
| `last_frame` | 尾帧输入字段，必须配套首帧映射 |
| `reference_images` | 1–9 个 `{ node_id, input }` 的列表；每份图片写入一个字段，提交图片数必须与列表长度一致 |

参考图片先经现有 Asset 与内容校验，再用 `POST /api/v2/assets` 上传。工作流输入写入标准资产引用 `{"__type":"core/ASSET","info":{"id":"已上传资产ID"}}`。上传接口的 `content_type`、`file_path` 位于 `file` 部件前面。本阶段不支持 ComfyUI 的远端视频或音频参考，会在提交前明确拒绝。

`capabilities` 必须提供：

| 字段 | 要求 |
| --- | --- |
| `modes` | 非空列表，取值为 `text`、`first_frame`、`first_last_frame`、`reference`；每种模式必须有相应映射 |
| `resolutions` | 非空列表，来自 `480p`、`720p`、`1080p` |
| `ratios` | 非空列表，来自现有六种画幅 |
| `min_duration` / `max_duration` | 4–15 秒范围内的整数上下界 |
| `generate_audio` / `watermark` | 支持的布尔值列表 |

能力声明必须来自实际工作流验证。启动和提交前会校验配置、映射和业务参数，但本地检查无法证明远程已安装模型与节点；远程服务仍会同步校验工作流。

`video_model_id` 及项目的“视频模型”字段在 ComfyUI 模式下保留为显示与历史记录标识，实际模型由工作流决定，修改该字段不会切换工作流里的模型。配置切换作用于新建视频任务，已有素材继续可用。

## 任务与下载语义

新视频任务保存 Provider、工作流、能力、远程地址和种子快照。旧任务没有 Provider 字段时固定按 Ark 处理。拿到 ComfyUI Job ID 后，在同一次任务更新中持久化 `external_id` 和响应中的 `urls.self`，后续按该链接轮询，支持带挂载前缀的服务。若链接缺失或指向其他服务，保留已受理的编号，改用原服务的标准任务查询入口。

| 服务结果 | 应用处理 |
| --- | --- |
| `queued` / `running` / `canceling` | 返回等待结果，由现有 Worker 延后轮询 |
| `succeeded` | 按指定输出节点和序号取视频，下载后探测、提取尾帧、保存 Asset，再进入现有 TOS 归档队列 |
| `failed` / `canceled` / `expired` | 终止错误，保留现有人工恢复与计费确认机制 |
| 连接建立前的连接或连接池异常 | 允许现有退避重试 |
| 提交写入、读取或协议异常；提交 5xx；重复幂等键；成功响应缺少有效 ID | 进入 `uncertain`，不自动重提 |
| 明确的 `429` 队列或限流拒绝 | 允许现有退避重试 |

提交使用 `Idempotency-Key`，由本地任务 ID、人工重提轮次标识和已记录的失败次数组成。人工恢复会清零失败次数，因此确认重提时另存新轮次标识，防止复用旧键；工作流与种子不变。Comfy v2 对重复键执行拒绝，不返回原任务；它不能替代本应用的 `uncertain` 处理。Worker 在提交阶段失去租约且没有 ID 时，也会进入人工核对。

人工查到已受理任务 ID 后，用现有恢复入口填写 ID，继续轮询原任务。若明确确认可能重复计费后重提，则仍遵循现有恢复机制。更换人工填写的 ID 时会清除原任务链接，按新 ID 查询。

下载器仅向快照指定的 ComfyUI 服务 API 地址发送 Bearer。跳转到云存储签名地址时不携带该密钥，继续使用 `MEDIA_ALLOWED_HOSTS` 和公网 HTTPS 校验；如远端使用其他存储域名，应由管理员明确加入现有允许列表。失败任务日志只记录经过筛选的状态与错误码，不输出响应正文、工作流或密钥。

视频地址不作为最终媒资保存。TOS 上传完成前，网页仍由现有 `media_ready` 判定是否可用；上传失败只由 `AssetBackup` 队列重试，不重新提交模型任务。

## 运行与部署边界

当前 CPU ECS 安装官方 ComfyUI 界面与 API 节点，默认通过 Ark 计算，另运行数据库、FFmpeg 和归档逻辑。若选择本文件中的远程视频 Provider，独立 GPU 环境还需运行可执行模型工作流的 ComfyUI，并在其旁部署 `comfy-api-proxy` 提供 v2 接口。CPU 服务的官方 `/prompt` 接口不会自动变成 v2 GPU 服务。

运行配置仍由 Terraform 写入 `runtime.json`，使用 cloud-init 的压缩文件编码，工作流正文不会放进源码发布对象。现有 User Data 大小限制继续生效，工作流过大时会明确拒绝。

本地 Compose 保持原入口。已有 `/config` 挂载可承载手工准备的 `runtime.json`；此时使用运行态字段 `workflow`（JSON 对象），不是 Terraform 字段 `workflow_json`，并设置可读取的 `api_key_file`，例如挂载目录中的专用密钥文件。不要把密钥正文写进 JSON。ComfyUI 模式必须启用私有 TOS 归档。

更新 Terraform User Data 不会让已有 ECS 自动重跑 cloud-init。用户手动切换配置时应遵循现有发布流程，并同时重启 API 和 Worker。所有历史任务结束前，应保留原远程服务及认证可用性；切换回 Ark 后仍有旧 ComfyUI 任务时，保留 `comfyui` 配置，以便 systemd 继续加载其凭据。

## 本地验证

源码仓库的 `tests/` 目录保存假服务集成用例和数据。从工程根目录执行，需安装 `backend/requirements.txt`、FFmpeg 和 FFprobe：

```bash
PYTHONPATH=backend PYTHONDONTWRITEBYTECODE=1 python tests/测试视频适配.py
terraform fmt -check -recursive
terraform validate
```

测试会自产自销本地 HTTP 服务、SQLite 数据库、视频、参考帧和假 TOS 数据，全部存放在系统临时目录并清理。它验证协议、任务状态持久化和媒体归档路径，不验证 PostgreSQL 的并发锁，也不证明实际模型工作流可运行。Ark 剧本与视频请求契约同时检查。

实际工作流尚未提供，远程 GPU 服务、认证、模型和私有 TOS 权限联调留给用户手动验证。

## 用户手动验收

1. 在 GPU 环境跑通实际工作流，核实模型、自定义节点、输入单位、参考模式、输出节点和规格，导出 API 格式 JSON。

2. 填写 `comfyui` 和两个必填模型服务密钥，先静态校验再发布。应用 ECS 的 ComfyUI 使用 API 节点，不安装本地视频模型。

3. 创建项目，确认剧本仍由 Ark 生成，视频走所选工作流。检查 `external_id`、排队、执行和成功状态。

4. 在完成提交后重启 Worker，确认继续查原任务；模拟提交响应丢失时确认进入 `uncertain`，填写远程 ID 后恢复轮询。

5. 核实下载结果进入私有 TOS，预览与下载使用 TOS 签名地址；模拟上传失败，确认只重试上传且模型任务数量不增加。

6. 恢复默认 Ark 配置并验证新建剧本、视频任务，同时保留旧 ComfyUI 任务需要的服务和认证。
